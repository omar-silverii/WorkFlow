----------------------------------------------------------------------
9.1 CONVENCIÓN DE input.filePath
----------------------------------------------------------------------

El Constructor IA actualmente viene generando:

path = input.filePath

Durante la revisión se detectó la posibilidad de que HDocLoad expanda
variables mediante una plantilla como:

${input.filePath}

Debe verificarse en el código real:

- qué convención acepta HDocLoad;
- cómo resuelven variables otros nodos;
- si path = input.filePath ya se resuelve;
- o si debe generarse path = ${input.filePath}.

No cambiar HDocLoad sin verificar.

La mejor corrección probablemente será ajustar el generador del
Constructor IA si la convención actual está mal.

Pero primero se debe inspeccionar el archivo real.

----------------------------------------------------------------------
9.2 RUTA ESTABLE DEL DOCUMENTO
----------------------------------------------------------------------

Riesgo:

El dispatcher puede crear una instancia con una ruta dentro de Inbox
y después mover el archivo a Processed.

La instancia seguiría conservando la ruta antigua.

Esto puede fallar si:

- una tarea humana pausa el workflow;
- más adelante otro nodo vuelve a leer el archivo;
- se intenta consultar el documento desde auditoría;
- el archivo ya no existe en la ruta inicial.

Solución conceptual recomendada:

Inbox
→ reclamar/mover archivo a Processing o Archive estable
→ crear instancia usando esa ruta definitiva
→ conservar esa ruta durante toda la instancia

No definir nombres o carpetas definitivas sin revisar el código real.

----------------------------------------------------------------------
9.3 SIGNIFICADO DE PROCESSED
----------------------------------------------------------------------

Si el runtime retorna al llegar a una tarea humana, el dispatcher
puede mover el archivo a Processed aunque el workflow esté EnCurso.

Entonces Processed puede significar:

- archivo recibido;
- archivo despachado;
- instancia iniciada;

y no necesariamente:

- workflow finalizado.

Se debe definir explícitamente esa semántica.

Opciones posibles:

- Accepted
- Dispatched
- Processing
- Archive
- Processed

No renombrar todavía sin analizar impacto.

----------------------------------------------------------------------
9.4 DUPLICADOS E IDEMPOTENCIA
----------------------------------------------------------------------

Mover el archivo fuera de Inbox reduce duplicados, pero no cubre:

- cierre del proceso después de crear instancia y antes de mover;
- dos dispatchers simultáneos;
- movimiento fallido;
- reinicio del worker;
- archivo copiado nuevamente;
- mismo contenido con otro nombre.

Debe verificarse si ya existe:

- registro persistente;
- clave de ingreso;
- hash;
- claim atómico;
- marca de procesamiento;
- control por ruta o nombre;
- transacción.

No inventar tabla nueva sin revisar la base.

----------------------------------------------------------------------
9.5 ESTADO REAL DE LA INSTANCIA
----------------------------------------------------------------------

El dispatcher podría considerar éxito simplemente porque la llamada
al runtime retornó sin excepción.

Debe verificarse:

- qué devuelve CrearInstanciaYEjecutarAsync;
- si retorna Id de instancia;
- si puede quedar EnCurso;
- si puede quedar Error sin lanzar excepción;
- cuándo se mueve a Error;
- cuándo se mueve a Processed.

La decisión de destino del archivo debe basarse en el resultado real,
no únicamente en ausencia de excepción.
